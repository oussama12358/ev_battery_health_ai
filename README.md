## **Purpose & Problem**

- **Purpose:** Provide a reproducible, deployable pipeline to predict battery State of Health (SoH) and Remaining Useful Life (RUL), surface root causes with explainability, and deliver actionable risk scores for fleet operations.
- **Problem solved:** Replace reactive, rule-based battery monitoring with a data-driven system that detects degradation early, predicts time-to-failure, and prioritises batteries for maintenance before failures occur.

## **Key Results (summary)**

- **Models & metrics:** Trained artifacts in [models/saved](models/saved/) (XGBoost/RF `.pkl`, LSTM `.keras` + weights) and `all_metrics.json` with MAE/RMSE/R². Representative SoH performance: R² ≈ 0.98, MAE ≈ 0.008–0.01.
- **Processed data & explainability:** [data/processed](data/processed/) includes `cycle_features.parquet`, `top_shap_features.csv`, and visuals such as [lstm_saliency_soh.png](data/processed/lstm_saliency_soh.png) and [shap_summary_xgb_soh.png](data/processed/shap_summary_xgb_soh.png).
- **Dashboard & API:** Interactive Streamlit dashboard at `app/dashboard.py` and FastAPI endpoints in `api/main.py` for programmatic inference.

## 📊 Dataset & Data Folder Structure

This project uses a **physics-inspired synthetic dataset** modelled after the [NASA Prognostics Center of Excellence Battery Dataset](https://www.nasa.gov/content/prognostics-center-of-excellence-data-set-repository):

| Property | Value |
|---|---|
| Cell type | Li-ion 18650 |
| Nominal capacity | 2.0 Ah |
| Voltage range | 2.7 – 4.2 V |
| Batteries | 34 simulated batteries (B0005–B0056) |
| Max cycles | ~200 per battery |
| Records | ~200,000 timestep rows |
| Features (cycle-level) | 38 engineered features |

**Why synthetic?** The real NASA dataset requires manual preprocessing from MATLAB `.mat` files. Our generator produces statistically equivalent data following the same exponential capacity-fade physics, making it reproducible and internship-portfolio ready. Swap `generate_battery_dataset()` with any real CSV loader — the pipeline is data-agnostic.

### Data Folder Organization

```
data/
├── raw/
│   └── battery_telemetry_raw.parquet (217 MB) ❌ NOT tracked in git
│       → Raw sensor readings (voltage, current, temperature) across cycles
│       → Generated by utils/data_generator.py on first run
│
└── processed/  ✅ TRACKED IN GIT
    ├── cycle_features.parquet (engineered 38-feature matrix)
    ├── annotated_features.parquet (anomaly labels from IsolationForest)
    ├── top_shap_features.csv (top 10 degradation drivers)
    └── *.png (9 visualizations: SHAP + EDA plots)
```

**Git Policy:**
- `data/raw/` → **Excluded** (regenerated on-demand via `python training/run_all.py`)
- `data/processed/` → **Included** (reproducible features + visuals for quick dashboard launch)

## 🚀 Quick Start

### 1. Clone & Install

```bash
git clone https://github.com/yourusername/ev-battery-health-ai.git
cd ev-battery-health-ai
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
```

### 2. Train All Models

```bash
python training/run_all.py
```

This will:
- Generate 200,000+ rows of battery telemetry
- Engineer 28 cycle-level features
- Train Random Forest + XGBoost baselines
- Train BiLSTM + Attention deep learning model
- Run SHAP explainability analysis
- Fit anomaly detector
- Save all models to `models/saved/`

**Estimated time:** 3–8 minutes on CPU.

### 3. Launch Dashboard

```bash
streamlit run app/dashboard.py
```

Open `http://localhost:8501` in your browser.

### 4. Launch REST API

```bash
uvicorn api.main:app --host 127.0.0.1 --port 8000 --reload
```

API docs: `http://localhost:8000/docs`

## 🧠 Explainable AI — Top Degradation Drivers

Based on SHAP analysis of the XGBoost SoH model:

| Rank | Feature | Physical Meaning |
|---|---|---|
| 1 | `ir_mean` | Internal resistance → primary aging proxy |
| 2 | `cumulative_throughput_ah` | Total lifetime charge stress |
| 3 | `dis_v_mean` | Mean discharge voltage correlates with capacity |
| 4 | `dis_t_max` | Peak temperature accelerates calendar aging |
| 5 | `v_drop_rate` | Voltage drop rate = acceleration of fade |
| 6 | `delta_ir_mean` | Rate of resistance growth |
| 7 | `cycle` | Direct aging indicator |

## ⚙️ Risk Scoring System

| Level | SoH | RUL | Action |
|---|---|---|---|
| 🟢 LOW | ≥ 85% | ≥ 50 cycles | Normal operation |
| 🟡 MEDIUM | 70–85% | 20–50 cycles | Reduce peak discharge, monitor temp |
| 🔴 HIGH | < 70% | < 20 cycles | Schedule replacement immediately |
